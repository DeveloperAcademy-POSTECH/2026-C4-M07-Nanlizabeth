# 👉 여기부터 읽으세요 — 2분 요약

우리가 만드는 것: **아이폰(왼손·코드) + 아이패드(오른손·스트로크)가 한 대의 기타가 되는 앱.** 한 대로도 연습 가능.

> 아래 상세 문서 3개가 있지만, **일단 이 페이지만.** → [무엇을(SPEC)](SPEC.md) · [어떻게(ARCHITECTURE)](ARCHITECTURE.md) · [순서·태스크(ROADMAP)](ROADMAP.md)

## 🧱 큰 그림: "3층 건물"을 아래부터 쌓는다

```
        3층  🖼️  화면들         (온보딩·기타넥·스트럼·선택·연결)
        2층  🧠  로직           (소리·박자·운지·주법·코드진행)
        1층  🧱  기반           (라우터·레이아웃 규약·디자인 토큰)
```

**바닥부터.** 1층 없이 3층 못 올린다. 이게 순서의 전부다.

---

## 🔢 순서: 뭘 · 왜 · 세부

### 1️⃣ 먼저 — 바닥 깔기 (기반)

**왜?** 이걸 안 정하면 각자 색·여백·화면이동을 제멋대로 만들어서 **나중에 절대 안 붙는다.**

- 레이아웃 규약(방향·크기) **한 가지로 합의**
- 디자인 토큰(색·여백·글자에 이름 붙이기)
- 라우터(화면 이동을 한 곳에서 관리)
- 폴더 정리 한 번

---

### 2️⃣ 그다음 — 껍데기(계약) 정하기 ⚡짧게

**왜?** 껍데기만 정해두면, 속을 몰라도 **모두가 동시에** 만들 수 있다. (콘센트 규격만 맞추면 어떤 가전이든 꽂히듯)

- "소리 내라", "박자 쳐라", "이 줄 눌렸다", "이 주법대로 긁어라", "이 코드진행 짚어라" 를 **껍데기로만** 정의
- **각 껍데기엔 '가짜 대역(Mock)'을 같이** 만든다 → 진짜가 없어도 개발 시작 가능
- ⚠️ 여기서 시간 끌지 말 것. 하나당 반나절.

---

### 3️⃣ 이제 — 동시에 채우기 (진짜 개발, 6갈래 병렬) 🚀

**왜?** 껍데기가 있으니 **서로 안 기다리고** 각자 자기 갈래를 판다. 여기가 개발의 몸통.

| 갈래 | 하는 일 |
|------|--------|
| 🎵 소리 | 두 엔진 성능 측정 (누굴 쓸진 나중에) |
| 🧠 로직 | 운지·주법·코드진행이 **즉각(지연 없이) 소리 나고 손끝 진동(햅틱)까지** |
| 📚 콘텐츠 | 리듬·코드진행(머니코드·캐논) **리서치해서 데이터로 입력** |
| 🖼️ 화면 | 피그마대로 예쁘게 + 줄 튕기는 애니메이션 (Mock으로 먼저) |
| 📡 통신 | 아이폰↔아이패드 연결 (아이패드=항상 오른손 고정) |
| 🎤 음성 | 연주 중 두 손이 바쁘니 **"머니코드로 바꿔"라고 말하면** 프리셋 전환 |

---

### 4️⃣ 마지막 — 조립 (플러그 꽂기)

**왜?** 껍데기가 같으니 **딸깍** 붙는다. 모드를 하나씩 켜서 확인.

- 모드 A: 내가 짚은 코드가 → 고른 주법으로 자동 연주
- 모드 B: 코드진행이 자동으로 → 나는 긁기만 연습
- 모드 C: 아이폰 짚기 × 아이패드 긁기 (두 기기 합주)

---

### 5️⃣ 진짜 맨 끝 — 소리 엔진 확정 ⏳

**왜?** 두 엔진(Native·AudioKit)을 **개발 내내 둘 다 살려두고** 발열·메모리를 재다가, **데이터가 가장 많이 쌓인 출시 직전**에 이긴 쪽으로 결정. 지금 안 정해도 아무것도 안 막힌다.

---

## ✅ 딱 두 가지 원칙만 기억하면 됨

1. **껍데기(계약) 먼저 → 그다음 각자 동시에.** (그래서 병렬이 됨)
2. **로직과 화면은 따로.** 로직은 화면 없이 돌고, 화면은 그걸 가져다 연결. (그래서 안 기다림)
