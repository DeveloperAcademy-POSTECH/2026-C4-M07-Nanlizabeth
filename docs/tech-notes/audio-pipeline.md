# 오디오 파이프라인: AVAudioEngine + AVAudioUnitSampler + SoundFont

> 이 문서는 "왜 이 기술을 골랐나"가 아니라 "이 기술이 어떻게 동작하나"를 설명하는 참고 자료입니다.
> 채택 근거는 [ADR 0002](../adr/0002-audio-engine.md) 참고.

## 핵심 개념: "재생"이 아니라 "합성"

코드별로 미리 녹음한 오디오 파일을 트는 방식은 6현을 개별 제어할 수 없고, 긁는 속도·방향에 따라 소리를 바꿀 수 없어 진짜 기타 느낌이 나지 않는다. 따라서 GuitarSync는 신디사이저처럼 "몇 번 현을, 이 세기로 울려라"라는 명령으로 소리를 **만들어내는** 방식을 쓴다.

## 신호 흐름

```
음원(Sampler) → 믹서 → [리버브 등 이펙트] → 스피커 출력
```

## 세 구성 요소

### ① AVAudioEngine — 오디오 작업 테이블
소리를 내는 부품들을 연결하고 최종 출력으로 내보내는 배선판(믹싱 콘솔).
엔진 자체는 소리를 만들지 않고, 부품들을 `attach` / `connect`로 이어 신호가 흐르게 한다.

### ② AVAudioUnitSampler — 실제로 음을 내는 악기
"몇 번 음을, 얼마나 세게 쳐라"라는 MIDI 명령을 받아 그 음을 울리는 전자 악기.

- 노트 켜기: `startNote(52, withVelocity: 100, onChannel: 0)` → 52번 음(E)을 세기 100으로 울림
- 노트 끄기: `stopNote(...)`

**스트럼의 구현 원리** — 스트럼은 결국 6개의 음을 아주 짧은 간격으로 순차적으로 켜는 것이다.
- 다운 스트로크: 저음현(6번) → 고음현(1번) 순으로 몇 ms 간격 `startNote`
- 업 스트로크: 반대 순서
- 세게 긁음: velocity 값을 높여 더 크고 밝은 소리

이 "현별 시차 + 순서 + 세기" 제어가 녹음 재생 방식으로는 불가능한 핵심 부분이다.

### ③ SoundFont (.sf2) — 악기가 쓸 음색 재료
Sampler는 빈 악기이므로 "어떤 소리로 울릴지"를 알려줘야 한다. 그 재료가 SoundFont다.
실제 악기 음을 음정별로 녹음해 묶어놓은 사운드 팩(`.sf2` 파일)으로, Sampler에 로드(`loadSoundBankInstrument(...)`)하면 노트 명령이 들어올 때 그 안의 실제 기타 샘플을 꺼내 울린다.

```
SoundFont(.sf2) → Sampler에 로드 → "기타 음색을 아는 악기"가 됨
                                      ↓
                "52번 음, 세기 100" 명령 → 진짜 기타 E음 출력
```

무료 기타 SoundFont를 구해 초기에 붙이고, 이후 GarageBand 음색이나 직접 녹음한 샘플로 교체 가능.

## 요약

| 구성 요소 | 역할 |
|-----------|------|
| AVAudioEngine | 소리 부품을 연결해 스피커로 내보내는 작업 테이블 |
| AVAudioUnitSampler | "몇 번 음을 이 세기로" 명령을 받아 음을 내는 악기 |
| SoundFont (.sf2) | 그 악기가 쓸 실제 기타 음색 샘플 모음 |

**전체 흐름:** 긁는 제스처 → 6현을 시차 두고 Sampler에 노트 명령 → 로드된 기타 SoundFont로 소리 출력

## 이 프로젝트에서 실제로 어떻게 쓰나 (구현 노트)

위는 원리다. 실제 코드는 여기에 세 가지가 더 얹혀 있다.

### ① 엔진이 두 벌이다 — 계약 뒤의 Native / AudioKit

`Domain/Audio/`에는 **두 엔진**이 있다: `NativeAudioEngine`(위에서 설명한 AVAudioEngine)과 `AudioKitAudioEngine`. 둘 다 `GuitarAudioEngineProtocol`을 구현하고, 공통 로직(음 계산·벨로시티·자동 정지)은 `GuitarAudioEngineBase`에 모여 있다(Template Method — 소리 내는 부분만 서브클래스가 오버라이드). 어느 쪽을 쓸지는 아직 안 정했고, **출시 직전에 데이터로 고른다.** → 왜 그렇게 하는지는 [ADR 0003](../adr/0003-dual-audio-engine-behind-contract.md).

### ② 소리가 조용히 죽지 않게 — `AudioSessionController`

전화·Siri·이어폰 분리·블루투스 전환·미디어 서비스 리셋이 오면 오디오 세션이 흔들려 **소리가 조용히 안 나게** 된다(오디오 앱에서 가장 흔한 버그). `AudioSessionController`가 `AVAudioSession` 알림을 받아 엔진을 되살린다:

- **중단(전화·Siri)** → 엔진 정지 → 끝나면 세션 재활성 + 재구동
- **경로 변경(이어폰 분리)** → 울리던 소리만 끊고(엔진 유지), 새 경로면 재구동
- **미디어 서비스 리셋** → 그래프 전면 재구축 (엔진·노드가 통째로 무효가 되므로 객체부터 새로 만든다)

> 재개 뒤 `isEngineRunning`을 **반드시 확인**한다. 경로가 바뀌면 하드웨어 포맷이 달라져 `engine.start()`가 **예외 없이 조용히 실패**하기 때문 — 확인 안 하면 복구했다고 믿지만 실제론 무음이다.

### ③ 함정: `stop()`은 음색을 날린다 → `pause()`를 쓴다

`AVAudioEngine.stop()`은 샘플러를 초기화 해제해 **로드해둔 SoundFont까지 날린다.** 그 상태로 다시 켜면 음정은 맞는데 음색만 기본음으로 떨어져 **기타가 사인파(신디사이저)처럼** 들린다. 그래서 화면을 잠깐 벗어났다 오는 것 같은 흔한 정지는 `stop()`이 아니라 **`pause()`**(렌더링만 멈추고 음색은 유지)로 처리한다. 그래도 음색이 빠졌을 수 있으니 켤 때 `isSoundFontLoaded`를 확인해 필요하면 다시 로드한다.

> **왜 이 노트가 중요한가:** "재생/합성"만 이해하면 데모는 되지만, **실사용(전화 받고, 이어폰 꽂고, 화면 오가는)에서 소리가 살아 있게** 하는 건 위 세 가지다. 악기 앱의 완성도는 여기서 갈린다. → 학습 관점 정리는 `docs/LEARNING-AREAS.md` 1️⃣.
