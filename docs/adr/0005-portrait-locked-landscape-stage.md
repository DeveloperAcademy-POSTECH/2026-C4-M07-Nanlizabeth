# ADR 0005: 가로 화면을 만드는 방식 — 세로 고정 회전(iPhone) + 네이티브 가로(iPad)

## 상태
채택됨 (Accepted, 2026-07-21 iPad 보강)

## 맥락

Chordly는 기타를 눕혀 든 **가로 화면**으로 연주한다. 화면 담당 여러 명이 각자 화면을 그리므로, "가로를 어떻게 만들고 어느 좌표계에 그리나"를 한 번에 정해두지 않으면 화면마다 방식이 달라져 나중에 안 붙는다.

기존 프로토타입은 앱을 **세로 고정**해두고 콘텐츠를 -90° 돌려 가로를 흉내 내고 있었다. 이 방식을 공식화할지, 시스템 회전에 맡길지 정해야 했다.

## 고려한 선택지

1. **시스템 회전에 맡긴다** (기기를 가로로 들면 iOS가 회전). 자연스럽지만, 기기를 조금만 기울여도 화면이 세로로 뒤집히고 회전 애니메이션이 튄다. 악기를 든 **자세가 고정된** 앱에는 산만하다.
2. **세로 고정 + 스테이지가 콘텐츠를 -90° 회전**시켜 가로를 만든다(`PortraitLockedLandscapeStage`). 기기를 돌려도 안 뒤집히고 애니메이션도 없다. 이미 동작하는 코드가 있어 교체 비용도 없다.
3. **기기별로 완전히 다른 레이아웃 시스템.** 유연하나 화면 담당이 기기 분기를 신경 써야 해 규약의 취지가 흐려진다.

## 결정

**세로 고정 + 회전 스테이지를 공식화하되, iPad는 예외로 둔다.**

- **화면 담당은 항상 하나의 가로 도화지(874×402, iPhone HI-FI 프레임)에만 좌표를 잡는다.** 스테이지가 이 도화지를 기기 크기에 맞게 통째로 비율 스케일(fit)한다. **기기 분기 금지.**
- 📱 **iPhone** = `Info.plist` 세로 고정 + 스테이지가 -90° 회전으로 가로 생성.
- 📲 **iPad** = **가로 네이티브**로 뜬다(`Info.plist ~ipad = Landscape`). 스테이지는 iPad에선 **회전하지 않는다**(`deviceType == .iPad` 분기). — iPad가 90° 돌아가던 문제를 없앤 2026-07-21 보강.

## 결과

**장점**
- 화면 담당은 **874×402 하나만** 생각하면 된다. 회전·스케일·기기차는 스테이지가 흡수한다.
- 기기를 돌려도 안 뒤집히고 회전 애니메이션이 없어, 악기 자세가 고정된 경험에 맞는다.

**감수하는 단점 / 유의점 — 반드시 챙길 것**
- 회전 방식(iPhone)이라 **시스템이 직접 띄우는 UI는 회전을 안 따라온다.** 실제 세로로 떠서 콘텐츠와 90° 어긋나 보인다:
  - **로컬 네트워크 권한 팝업** → 연결 가이드에서 "옆으로 보일 수 있어요"까지 예고.
  - **`MPVolumeView` 볼륨 슬라이더** → 온보딩에서 예외 처리.
  - **VoiceOver 순서** → 자동 순서 대신 명시적으로 지정(H4).
- **iPad 전용 레이아웃은 아직 없다.** 지금은 iPhone 도화지(2.17:1)를 iPad 화면(1.33:1)에 넣어 **위아래 여백**이 생긴다. Figma `iPad Pro 12.9"` 프레임 기준 4:3 재배치(사운드홀 크게, 줄이 화면을 관통)는 SPEC §8 결정 후 `LayoutTokens.padStage` 기준으로 새로 짠다.

## 관련
- 코드에서의 규약·예외 3종 표 → ARCHITECTURE §2.5.
- 물리 거리가 필요한 계산(제스처 임계값·스트럼 속도)에만 `@Environment(\.stageScale)`을 곱한다.
